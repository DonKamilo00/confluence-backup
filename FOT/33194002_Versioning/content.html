Purpose

This document defines how versions are numbered and communicated across iOS and Android.

Consistency here reduces confusion for:

  • Users

  • App stores

  • Internal operations

Versioning Format

wide760

Examples

  • 1.0.0 → Initial release

  • 1.1.0 → New features

  • 1.1.1 → Bug fixes

When to Increment

MAJOR

  • Architectural changes

  • Large UX shifts

  • Platform-wide changes

MINOR

  • New features

  • Significant improvements

PATCH

  • Bug fixes

  • UI polish

  • Performance improvements

Platform Rules

  • iOS & Android share semantic versions

  • Build numbers remain platform-specific

  • One platform can release independently if required

Changelog Rules

Every release must include:

  • What changed

  • Why it matters

  • User-facing clarity

Avoid

  • Technical jargon

  • Internal references

  • Over-verbosity

Hotfixes

  • Use PATCH increment

  • Keep scope minimal

  • Document reason clearly

Documentation Rule

No release is complete until:

  • Version is documented

  • Changelog is written

  • Store metadata is updated

Closing Note

Versioning is not cosmetic — it’s trust infrastructure.

Clear versions = calm operations.
