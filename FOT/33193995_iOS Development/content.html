Purpose

This document defines the end-to-end iOS workflow, from development to App Store release.

1. Local Development

Used for

  • Feature development

  • UI/UX changes

  • Logic updates

Tools

  • Expo CLI

  • iOS Simulator or physical iPhone

2. Expo Go (Early Testing)

Purpose

  • Fast iteration

  • Visual & logic validation

Limitations

  • No native modules

  • No push notifications

  • No Apple-specific APIs

Expo Go is never used for final QA.

3. Development Build (EAS)

Purpose

  • Native feature testing

  • Real-world behavior validation

Command

wide760

Installed via

  • Direct install link

  • Internal TestFlight

4. iOS QA

Checks

  • App launch & cold start

  • Permissions copy

  • ND-critical flows

  • Crash-free navigation

  • Performance sanity check

5. TestFlight

Used for

  • Final QA

  • Apple review simulation

  • Stability confidence

6. App Store Release

Steps

  1. Increment version & build number

  2. Create production build

  3. Upload to App Store Connect

  4. Submit for review

  5. Monitor approval & post-release health

Post-Release

  • Monitor crashes

  • Review analytics

  • Address urgent regressions if needed
