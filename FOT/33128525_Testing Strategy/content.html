Purpose of This Document

This document defines how MyndMap is tested to ensure reliability, clarity, and trust across iOS and Android.

Testing at MyndMap is not about perfection — it is about confidence.

Testing Philosophy

  • Manual testing is primary

  • Automation may be added later

  • Human experience > synthetic tests

  • ND-specific flows are first-class citizens

Testing Layers

1. Development Testing

Who: Jordan
Where: Local / Expo Go

  • Logic validation

  • UI iteration

  • Early regression spotting

2. Development Build Testing

Who:

  • iOS: Jordan

  • Android: Kamil

Where: EAS development builds

  • Native features

  • Push notifications

  • Background behavior

  • Permissions

3. Platform-Specific QA

iOS

  • Cold start

  • App lifecycle events

  • Permission prompts

  • Navigation consistency

Android

  • Device fragmentation

  • Battery usage

  • OS version differences

  • Background task behavior

4. ND-Specific Flow Testing

Explicitly test:

  • Task overwhelm scenarios

  • Notification tone & frequency

  • Recovery from missed tasks

  • Cognitive clarity during stress

Device Coverage

iOS

  • Latest iOS version

  • One older device model

Android

  • Pixel-class device

  • Samsung-class device

  • Low-RAM / budget device (where possible)

Release Blocking Rule

Any tester may block a release if:

  • A regression is detected

  • Core flows feel degraded

  • Platform-specific instability is present

No release proceeds without sign-off.

Documentation

All notable findings:

  • Are logged

  • Are discussed before release

  • Influence future testing priorities

Closing Note

Testing is not a gate — it is a shield.
