🚨 Incident Report: Android Native Build Compilation Failure

Date & Time: 2026-02-12 | Multiple sessions
Owner: Kamil Maruszak
Platform: Android (Windows Development Environment)
Status: ✅ Resolved

Incident Summary

The Android native build pipeline failed with multiple sequential compilation errors when attempting to generate an APK via EAS Build. The build process was blocked by Gradle dependency conflicts, deprecated API usage, missing manifest configurations, and asset compilation issues. This prevented delivery of testable Android builds for internal testing and QA validation.

Severity Classification

Level: P1 — High

Reason:

  • Platform-specific blocking issue: Complete inability to generate Android builds

  • Multi-day blockage of QA and testing workflow

  • Impacts release timeline and internal stakeholder confidence

Impact:

  • Blocked all Android build generation (both local and cloud)

  • Prevented testing of core features on Android devices

  • Required deep technical investigation across build toolchain

Platform(s) Affected

  • Primary: Android (EAS Build & Local Gradle)

  • Environment: Windows development machine

  • Build Tools: Gradle 8.14.3, Expo SDK, React Native 0.80+

Timeline of Events

Initial Detection

  • EAS Build triggered via eas build --platform android

  • First failure: Gradle variant ambiguity in react-native-iap library

Sequential Failures (Cascade Pattern)

  1. Product Flavor Conflict - react-native-iap multiple flavors (amazon/play)

  2. Deprecated API Error - react-native-iap@12.16.4 using removed currentActivity API

  3. Manifest Placeholder Error - react-native-app-auth missing appAuthRedirectScheme configuration

  4. PNG Compilation Failure - AAPT2 rejected src_assets_images_lumen.png

  5. Git Line Ending Warnings - CRLF/LF conflicts on Windows with Mac collaborator

Root Cause Analysis

1. Product Flavor Ambiguity

Cause: react-native-iap library defines multiple product flavors (Amazon/Google Play) but app configuration didn't specify which to use.

Preventative Actions

1. Pre-Build Validation Script

2. Dependency Update Protocol

  • When upgrading packages with patches, always delete old patch files

  • Run npx patch-package to regenerate if still needed

  • Document why patches exist in README.md

3. Asset Validation Pipeline

  • Add pre-commit hook to validate PNG compatibility

  • Use ImageMagick or similar to normalize all PNGs during asset import

  • Document Android AAPT2 requirements in asset guidelines

4. Cross-Platform Development Standards

  • Enforce .gitattributes in all repositories

  • Add to project template/boilerplate

  • Document in onboarding materials

5. Build Configuration Documentation

  • Document all custom Gradle configurations

  • Maintain changelog for android/app/build.gradle modifications

  • Link to relevant GitHub issues/RN upgrade guides

6. EAS Build Profile Strategy

Update eas.json to clearly separate APK vs AAB builds:

  • preview → APK (for internal testing)

  • production → AAB (for Play Store)

  • Document which profile to use for which purpose

Lessons Learned

What Went Well

  • Systematic debugging approach (fixed one error at a time)

  • Cloud builds (EAS) provided consistent, reproducible environment

  • Detailed error logs enabled precise diagnosis

What Could Be Improved

  • Earlier detection via local build testing before cloud builds

  • Automated dependency compatibility checks

  • Better documentation of Android-specific requirements

Knowledge Gaps Closed

  • Understanding of Gradle product flavors

  • AAPT2 PNG validation requirements vs Metro bundler

  • React Native API deprecation patterns

  • Cross-platform Git line ending management

Final Notes

This incident highlights the complexity of the React Native native build toolchain and the importance of:

  1. Incremental debugging - Solving one error at a time prevents confusion

  2. Version awareness - Patches and configurations are version-specific

  3. Platform parity testing - Expo Go ≠ Native builds

  4. Team environment diversity - Windows + Mac requires explicit Git configuration

Operational Maturity: This incident improved our build pipeline robustness and documentation. Future Android build issues will be detected and resolved faster.
