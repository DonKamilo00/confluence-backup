Purpose

This page defines how Firebase security rules are written and enforced.

Security rules are part of the product.

Core Philosophy

  • Default deny

  • Least privilege

  • Explicit access only

  • Assume malicious intent

User-Scoped Access

Rules must ensure:

  • Users can only read their own data

  • Writes are validated

  • Cross-user access is impossible

No rule should rely on “client honesty”.

Validation Rules

Rules should validate:

  • Required fields

  • Field types

  • Ownership

  • Write intent

Invalid writes must fail loudly.

Rules Testing

  • Rules are tested before release

  • Changes are reviewed deliberately

  • No emergency rule changes without documentation

Golden Rule

If a rule feels “temporary”,
it probably shouldn’t exist.
