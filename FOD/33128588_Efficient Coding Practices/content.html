Purpose

This page documents how MyndMap keeps velocity high without accumulating chaos.

Efficiency is achieved through structure — not shortcuts.

Keeping Screens Small

Screens should:

  • Coordinate features

  • Render layout

  • Handle navigation

They should not:

  • Contain business logic

  • Own complex state machines

  • Implement long procedural flows

When a screen grows:

  • Extract feature blocks into components

  • Extract logic into custom hooks

Custom Hooks Patterns

Custom hooks are used for:

  • Data fetching

  • Side effects

  • Subscriptions

  • Complex state logic

Rules:

  • Hooks return data + actions

  • Hooks do not render UI

  • Hooks are composable

This keeps UI components clean and readable.

Memoization Guidelines

Use memoization when:

  • Props are stable

  • Renders are frequent

  • Components are heavy

Avoid memoization when:

  • Components are small

  • Props change often

  • It adds mental overhead without benefit

Memoization is a tool — not a default.

Golden Rule

Code should be:

  • Easy to delete

  • Easy to refactor

  • Easy to reason about
