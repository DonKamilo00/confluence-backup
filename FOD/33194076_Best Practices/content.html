Purpose

This page defines the baseline React Native standards used across MyndMap.
These rules exist to ensure consistency, maintainability, and predictable performance across iOS and Android.

These are not suggestions — they are defaults.

Component Structure Rules

Container vs Presentational

Containers

  • Handle data fetching

  • Manage state

  • Orchestrate logic

  • Pass clean props downward

Presentational Components

  • Render UI only

  • No side effects

  • No direct data fetching

  • Minimal logic

Screens should orchestrate, not implement.

If a screen grows beyond a few responsibilities, logic must be extracted.

Hooks Rules

useEffect Discipline

  • Every useEffect must have:

    • A clear reason for existing

    • Correct dependencies

    • Cleanup if subscribing to anything

Avoid:

  • “God effects”

  • Effects that do multiple unrelated things

  • Effects triggered by unstable dependencies

Stable Callbacks

  • Use useCallback only when:

    • Passing callbacks to memoized children

    • Preventing unnecessary re-renders

Do not cargo-cult memoization.

Styling Rules

StyleSheet First

  • Always prefer StyleSheet.create

  • Avoid inline styles in render

  • Use shared design tokens where possible

Inline styles:

  • Increase render churn

  • Obscure consistency

  • Hide performance issues

Navigation Rules

  • Screens own navigation orchestration

  • Components do not navigate unless explicitly designed to

  • Navigation params must be:

    • Typed (when possible)

    • Minimal

    • Serializable

Deep links must route to screens, not components.

Golden Rule

If someone new opens a file:

  • Its responsibility should be obvious within 30 seconds
