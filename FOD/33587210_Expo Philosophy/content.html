This page defines the mental model for using Expo Go correctly.

Misunderstanding Expo Go leads to:

  • False confidence

  • Missed bugs

  • Broken releases

Core Philosophy

Expo Go exists to answer:

“Does this logic or UI make sense at all?”

It does not answer:

“Is this production-ready?”

Boundaries

Allowed

  • UI layout & spacing

  • Navigation flow

  • Copy changes

  • Non-native logic

  • Early feature scaffolding

Disallowed

  • Native API validation

  • Push notification testing

  • Background tasks

  • Performance benchmarking

  • Release sign-off

Golden Rule

If a feature touches the OS,
Expo Go is no longer sufficient.
