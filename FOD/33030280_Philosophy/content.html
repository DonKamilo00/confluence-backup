Purpose

This page defines why Firebase is used at MyndMap, what responsibilities it holds, and—critically—what it is notresponsible for.

Firebase is treated as infrastructure, not business logic.

Why Firebase

Firebase is used because it provides:

  • Rapid iteration

  • Cross-platform support

  • Managed authentication

  • Scalable data storage

It enables MyndMap to move fast without maintaining a custom backend early on.

What Firebase Is Responsible For

  • Authentication & identity

  • User-scoped data storage

  • Real-time or near-real-time sync (where justified)

  • Offline-aware persistence

What Firebase Is Not Responsible For

  • Business rules

  • Heavy computation

  • Costly aggregation logic

  • AI orchestration

  • Analytics-driven decisions

Those responsibilities live in:

  • App logic

  • Services

  • External APIs

Design Philosophy

  • Reads are expensive — design to minimize them

  • Writes should be intentional

  • Data should be easy to reason about

  • Firebase should always be replaceable

Golden Rule

If Firebase disappeared tomorrow,
MyndMap should still make sense conceptually.
