Purpose

This page defines how user identity and authentication are handled safely and predictably.

Authentication is a trust boundary.

Authentication Model

  • Firebase Auth is the single source of identity

  • Each user has a unique UID

  • All user data is scoped to that UID

No shared or anonymous cross-user access is allowed.

Session Handling (React Native)

Rules:

  • Auth state is observed centrally

  • UI reacts to auth changes

  • No screen assumes auth without validation

Auth listeners must:

  • Be registered once

  • Be cleaned up properly

  • Never leak across app restarts

Logout & Edge Cases

On logout:

  • Clear local state

  • Remove listeners

  • Reset navigation

Expired sessions must:

  • Fail gracefully

  • Redirect cleanly

  • Never crash the app

Security Considerations

  • Tokens are never logged

  • Sensitive auth data is never stored manually

  • All auth flows assume network instability

Golden Rule

If auth fails, the app must remain calm and recoverable.
