Purpose

This page defines the developer tooling baseline used to maintain quality and reduce friction.

Good tooling prevents bad decisions.

ESLint & Prettier

  • Enforced formatting

  • Consistent code style

  • Reduced cognitive overhead

Rules should:

  • Catch bugs

  • Avoid over-strict noise

  • Be consistently applied

TypeScript Strategy

TypeScript is adopted incrementally.

Approach:

  • New files → typed

  • Critical paths → typed first

  • No blocking migrations

Type safety is added where it provides real value.

Debugging Stack

Primary tools:

  • Expo Dev Client

  • React DevTools

  • Flipper (where useful)

Debugging rules:

  • Prefer inspecting state over logging

  • Remove debug logs before release

  • Never ship noisy logging

Error Monitoring

Use:

  • Sentry or Crashlytics

  • Release tagging enabled

Errors must be:

  • Actionable

  • Reproducible

  • Prioritized

Silent failures are unacceptable.

Golden Rule

If a bug happens in production:

  • We should know

  • We should know where

  • We should know why
