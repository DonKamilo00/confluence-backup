Purpose

This page defines how Firestore is used, structured, and queried to avoid performance and cost issues.

Data Modelling Principles

  • Shallow hierarchies

  • Predictable document shapes

  • Avoid deeply nested collections

  • Prefer explicit fields over implicit meaning

Documents should be understandable without context.

Collections vs Documents

Use collections when:

  • Data repeats

  • Items grow unbounded

Use documents when:

  • Data is singular

  • Access is frequent

Never store large arrays that grow indefinitely.

Querying Rules

  • Always query with intent

  • Use indexes deliberately

  • Avoid unbounded queries

  • Paginate where possible

Real-time listeners are opt-in, not default.

Offline & Caching

  • Assume intermittent connectivity

  • Cache intelligently

  • Avoid refetch loops

  • Handle stale data gracefully

Offline is a first-class scenario.

Golden Rule

If you can’t explain a query’s cost,
don’t ship it.
