This document defines how the live MyndMap website is accessed and updated safely and consistently.

It exists to:

  • Prevent accidental site breakage

  • Ensure shared access without leaking credentials

  • Make website updates repeatable and low-stress

  • Align website changes with app and marketing updates

Credential Management (Critical)

🔐 Where Credentials Live

All website credentials are stored in:

KeePassXC

🚫 Credentials are never stored in:

  • Confluence

  • Jira

  • GitHub

  • Slack / chat tools

  • Plain text files

If credentials need to change:

  • Update KeePassXC

  • Notify relevant contributors

  • Do not paste them elsewhere

Step 1: Access Namecheap

  1. Navigate to:
    https://www.namecheap.com

  2. Click Account (top-right)

  3. Log in using the credentials stored in KeePassXC

If you cannot log in, check KeePassXC first before escalating.

Step 2: Locate Hosting

  1. Once logged in, open the Account Dashboard

  2. Navigate to Hosting List

  3. Locate the active MyndMap hosting plan

  4. Click Go to cPanel

This opens the hosting control panel for the live site.

Step 3: Access File Manager

Inside cPanel:

  1. Locate the Files section

  2. Click File Manager

  3. When prompted:

    • Select Web Root (public_html)

    • Ensure correct domain is selected (if multiple)

Step 4: public_html (Live Website Root)

public_html is the live root directory of the website.

Important rules:

  • Any change here is immediately live

  • There is no staging environment by default

  • Changes should be deliberate and reviewed

Typical contents may include:

  • index.html

  • CSS / JS assets

  • Image folders

  • Subdirectories for pages

Step 5: Updating the Website (Safe Workflow)

Recommended Local Workflow

  1. Make changes locally first

    • Use Live Server or equivalent

    • Test layout, responsiveness, copy

  2. Verify changes match:

    • Current app behavior

    • Fountain of Marketing principles

  3. Prepare only the files that changed

Uploading Changes

Inside File Manager:

  • Upload files via:

    • Drag & drop

    • Upload button

  • Replace files intentionally

  • Avoid deleting unknown files

🚫 Do not:

  • Upload unnecessary build artifacts

  • Rename files casually

  • Change directory structure without reason

Step 6: Post-Update Verification

After upload:

  • Refresh the live website

  • Check:

    • Layout integrity

    • Mobile responsiveness

    • Broken links

    • Visual regressions

  • Cross-check against:

    • App UI

    • Blog references

    • Marketing copy

Coordination Rules

Website updates should:

  • Be aligned with product reality

  • Be documented if significant

  • Be coordinated with marketing when user-facing

Large updates should be:

  • Reviewed by Jordan

  • Logged in Jira (if applicable)

Common Failure Modes (Avoid)

  • Editing directly in cPanel without local testing

  • Leaving backup files visible

  • Forgetting mobile layout

  • Publishing future promises accidentally

  • Sharing credentials outside KeePassXC

Golden Rule

The website is a promise.
If it’s wrong, trust erodes immediately.

Treat updates with the same care as app releases.
