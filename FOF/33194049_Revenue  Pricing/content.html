Purpose of This Document

This page defines how MyndMap makes money, why pricing is structured the way it is, and how revenue aligns with user trust and product integrity.

Revenue is designed to sustain clarity, not extract value.

Revenue Philosophy

  • Value before monetization

  • No dark patterns

  • Paid features must feel worth it

  • Free users are respected users

Core Revenue Model

Freemium Subscription Model

  • Free Tier

    • Core task management

    • Non-punitive reminders

    • Baseline organization features

  • Premium Tier

    • AI-powered features (OpenAI-backed)

    • Advanced insights & reflections

    • Higher personalization depth

Premium exists to:

  • Offset infrastructure costs

  • Fund continued development

  • Reward power users without penalizing others

Platform Billing

  • iOS: Apple in-app subscriptions

  • Android: Google Play subscriptions

Platform-native billing is used to:

  • Reduce friction

  • Increase trust

  • Ensure compliance

Pricing Logic

Pricing is based on:

  1. Marginal Cost

    • API usage

    • Infrastructure load

  2. Perceived Value

    • Time saved

    • Mental clarity gained

    • Reduced cognitive load

  3. Market Sensitivity

    • Accessibility for ND users

    • Regional pricing flexibility (future)

AI Feature Monetization

AI-powered features are never free by default due to:

  • Variable API cost

  • Abuse prevention

  • Sustainability concerns

Rules:

  • AI usage is gated

  • Usage scales with plan

  • Cost is directly linked to value delivered

Future Revenue Considerations

  • Tiered premium plans

  • Family / shared plans

  • Institutional or educational access

  • Partnerships (non-invasive)

All future revenue must:

  • Preserve user trust

  • Avoid bloating the product

Closing Note

MyndMap earns by being useful —
not by being addictive.
